项目可以不接外部仓库，由 Oryn 保存正本：仓库就是控制面上的 `<data_dir>/repos/<项目 id>.git`，控制面自己提供 smart-HTTP，克隆地址是 `https://<Oryn 地址>/git/<项目 id>.git`。项目主页的提交、文件、README 与各子页和[仓库浏览](/guide/projects/repo-browser/)一样，读的就是正本本身；没有同步的概念，仓库行没有同步状态与「立即同步」。

托管项目在仓库行、总览与首屏的项目选项里写「Oryn 托管」。设置「概览」的「托管仓库」卡显示克隆地址（可复制，下面写着对应的 `oryn clone` 命令）与推送后 Webhook。

## 新建托管仓库

在[新建项目](/guide/projects/manage/)时，「仓库」选「空白仓库（Oryn 托管）」。仓库建好就带一个空树的初始提交 `Initial commit`（没有 README），基线分支缺省 `main`。提交作者依次取项目的 git 作者、全局 git 身份，都没有时为 `Oryn <oryn@<Oryn 主机名>>`。

等价命令（先 `oryn login`），输出项目 id：

```bash
oryn project create <项目名> --hosted
```

没有仓库的旧项目可以在设置「概览」的「托管仓库」卡里点「创建托管仓库」；已归档的项目要先取消归档。之后新建的执行环境（orb）会克隆它，正在运行的环境不受影响。

托管与外部仓库不能互转：托管项目不能再填外部仓库地址，有外部仓库的项目也不能创建托管仓库。

## 把本机已有的仓库建成托管项目

在本机仓库里运行（先 `oryn login`）：

```bash
oryn project create <项目名> --push
```

命令以当前分支为基线，在服务端建一个没有提交的空仓库，然后在本机加远端（缺省 `origin`）、登记凭据助手，再 `git push -u`。

- 已有 `origin` 时报错并提示 `--remote`，例如 `--remote oryn`。
- 仓库里有 Git LFS 文件时先 `git lfs push --all`；本机没装 git-lfs 时不建项目。

分离 HEAD、还没有提交的分支、不是 git 工作区，都会在建项目之前报错。推送失败时项目保留，按提示重跑 `git push -u <远端> <分支>`。

## 在本机克隆

```bash
oryn clone <项目名或 id> [目录]
```

目录缺省是项目名。`oryn clone` 克隆托管仓库，并在新仓库里把 `oryn git-credential` 登记为该主机的凭据助手：先清空这台主机的其它助手，设备令牌不会被系统钥匙串之类的助手存走。之后的 fetch、push 与 `git lfs` 都用 `oryn login` 的设备令牌认证。

- 克隆地址的主机与登录的服务器不同时直接报错，提示用 `oryn login --url` 重新登录。
- 外部仓库的项目会提示直接 `git clone <地址>`。

`/git/` 只认设备令牌（HTTP Basic 的密码位，用户名任意；或 `Bearer`），浏览器的登录会话不能用来访问它。

## 环境里如何访问托管仓库

托管项目的环境从克隆地址克隆，`git remote -v` 显示的就是它。环境里的 git 与 LFS 请求经出站代理回到控制面在本地服务，不出网、不注入任何令牌。

- 环境只能访问本项目的托管仓库，同一 Oryn 地址上别的托管仓库返回 `403`。
- 只读评审线程不能推送。
- Agent 推上来的对象先过 `git fsck`：带 `.git` 路径项或恶意 `.gitmodules` 的树进不来。

规则全貌见 [Git 访问范围与门禁](/security/git-scope/)。

## 交付线程的改动

托管项目的改动面板是「提交并推送到 `<基线>`」。它给线程发一段固定提示词，让 Agent 提交、rebase 到 `origin/<基线>`、`git push origin HEAD:<基线>`；被拒时重来，不强推。

线程把提交推上项目基线分支后自动标记「已交付」，推送带来的提交关联到这个线程（来源「由该线程推送」）。你在本机的推送不关联线程，只刷新页面并触发 Webhook。改动面板的其它操作见[查看改动、提交与开 PR](/guide/workbench/changes/)。

## 配置推送后 Webhook

只有托管项目有推送后 Webhook，只有你本人能在设置「概览」的「托管仓库」卡里改，全局助手改不了。

- 地址须是 `http://` 或 `https://`，不能带用户名密码。
- 签名密钥可选，保存后不再显示；留空保存表示不改，「清除密钥」去掉签名。
- 设置里显示最近一次投递的时间与 HTTP 状态码，或失败原因。

每次推送成功后异步 POST 一次 JSON：不阻塞推送、不重试、不跟随重定向（3xx 算失败），10 秒超时；同一项目同一时刻只投一个，积压超过 8 个时丢弃这次并记为失败。

线程里 Agent 的推送同样触发（`pusher.kind` 为 `thread`）。要不要据此部署，由接收端把关。

### 请求头

| 头 | 值 |
|---|---|
| `Content-Type` | `application/json` |
| `User-Agent` | `Oryn-Webhook/<版本>` |
| `X-Oryn-Event` | `push` |
| `X-Oryn-Delivery` | `<deliveryId>` |
| `X-Oryn-Signature-256` | `sha256=<hex(HMAC-SHA256(密钥, 原始请求体))>`，只在设了密钥时出现 |

### 载荷

```json
{"event":"push","deliveryId":"whd_01J…","pushedAt":1795000000000,
 "project":{"id":"prj_…","name":"demo","cloneUrl":"https://oryn.example.com/git/prj_….git"},
 "pusher":{"kind":"thread","threadId":"T-…"},
 "refs":[{"ref":"refs/heads/main","oldSha":"<40 位十六进制>","newSha":"<40 位十六进制>"}]}
```

- `pusher` 是 `{"kind":"owner"}`（你在本机推送）或 `{"kind":"thread","threadId":…}`（环境里的 Agent；找不到唯一的工作线程时不带 `threadId`）。
- `refs` 是这次推送改动的全部 ref。新建分支的 `oldSha`、删除分支的 `newSha` 是 40 个 `0`。

### 验签

接收端按原始请求体校验签名，例如：

```python
import hashlib, hmac

def verify(secret: bytes, body: bytes, header: str) -> bool:
    expected = "sha256=" + hmac.new(secret, body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, header)
```

## 找回被强推或删除的分支

基线分支不设保护：任何分支都可以强推或删除。被删除或被强推覆盖的分支，旧值在仓库里留存 30 天，存为 `refs/oryn/saved/<毫秒时间戳>/heads/<分支>`。这些 ref 对 git 客户端不可见，也改不了。

需要时在控制面主机上以控制面的运行用户取回：

```bash
# 列出留存的旧值
git --git-dir <data_dir>/repos/<项目 id>.git for-each-ref refs/oryn/saved/
# 用找到的 ref 建一个新分支
git --git-dir <data_dir>/repos/<项目 id>.git branch <新分支名> <那个 ref>
```

## 使用 Git LFS

托管仓库内置 LFS 服务（批量接口与 basic 传输），本机与环境都能用：`oryn clone` 之后 `git lfs` 自动带设备令牌，环境里经出站代理。

- 不支持文件锁：锁接口一律回 404，git-lfs 据此自动关掉推送前的锁校验。
- 对象存在仓库目录的 `lfs/objects/` 下，计入仓库大小，随项目删除。
- 网页上超过 100 MiB 的 LFS 文件只能下载。

## 归档与删除

归档后仓库只读：能克隆，不能推送，也不能上传 LFS 对象。

<Aside type="caution">
删除项目会连仓库一起删除，包括全部分支、标签、提交与 LFS 对象，不可恢复。托管仓库没有别的副本，备份见[备份](/admin/operations/backup/)。
</Aside>

## 限制

| 项 | 值 |
|---|---|
| 仓库大小 | 不设上限，也不额外安排清理 |
| 推送与 LFS 上传 | 数据盘可用空间低于 `repos.min_free_gb`（缺省 2 GiB）时拒绝 |
| 被覆盖分支的留存 | 30 天 |
| Webhook 超时 | 10 秒，不重试 |
| Webhook 积压 | 每个项目超过 8 个时丢弃 |
| 网页上可预览的 LFS 文件 | 100 MiB |
