项目主页上的提交、文件与 README 不经过任何执行环境（orb）：控制面为每个外部仓库维护一份裸镜像 `<data_dir>/repos/<项目 id>.git`，包含全部分支与标签，不含 PR 引用，由控制面自己执行 `git`。只支持 `https://` 仓库地址。Oryn 托管的仓库直接读正本，没有同步的概念，见[托管仓库](/guide/projects/hosted-repo/)。

## 浏览提交、分支与文件

项目主页上和仓库有关的区块：

- 描述与仓库行末尾是同步状态（已同步多久前、克隆中、同步中、同步失败的原因）与刷新按钮。
- 「最近线程」旁是「提交到 `<基线>`」：基线分支最近 5 个提交，带关联线程的直接链到线程。
- 「文件」：进入提交 / 分支 / 标签子页的入口、最新提交、根目录列表与每项最后一次改动的提交。
- README：根目录里的 `README.md` 等，按 GitHub 的规则解析相对链接与相对图片，超过 512 KB 截断。

子页：

| 地址 | 内容 |
|---|---|
| `/projects/<id>/commits` | 提交列表，可切换分支或标签（`?ref=`）；宽屏左列表右详情，详情列出改动文件，逐个展开看 diff |
| `/projects/<id>/branches` | 分支，默认分支排第一，每行可进该 ref 的文件 |
| `/projects/<id>/tags` | 标签，每行可进该 ref 的文件 |
| `/projects/<id>/files/<路径>` | 目录列表或文件预览，只读，地址可直接分享 |

## 同步镜像

镜像按下面的规则更新：

- 首次打开项目页（或调用任一仓库接口）时在后台克隆，页面先显示「克隆中…」。
- 之后每次读取时，距上次拉取超过 60 秒就在后台拉取，读取先返回旧数据。
- GitHub 项目另订阅仓库的 `push` 事件，推送后立即拉取。
- 首次克隆失败后不自动重试，等手动同步或推送事件。
- 已归档的项目不自动克隆、不自动拉取，只能手动同步。

要立即同步，点仓库行末尾的刷新按钮，或设置「概览」里「仓库镜像」卡上的「立即同步」。

改了仓库地址（指向另一个仓库）时，旧镜像被删掉，按新地址重新克隆；GitHub 仓库改名（绑定的仓库 id 不变）只更新地址。删除项目时镜像一起删除。

已有镜像时拉取失败不影响浏览：继续显示旧数据，同步状态旁有告警图标说明最近一次失败的原因。

## 为私有仓库提供凭据

镜像按仓库主机取令牌：

| 主机 | 用哪份凭据 |
|---|---|
| github.com | 你的 GitHub 账号令牌；没连接时匿名。项目里设的 `git/github.com/token` 不用于镜像 |
| 其它主机 | 先用项目设置「密钥与环境变量」里的 `git/<主机>/token`，没有再用全局密钥 `git/<主机>/token` |

令牌只经环境变量交给 git，不写进命令行与磁盘配置。没有令牌的非 GitHub 主机经公网地址守卫直连：只连 443 端口、只连公网地址，解析到内网的主机会被拦截。

添加项目令牌见[密钥与环境变量](/guide/projects/secrets/)，连接 GitHub 账号见 [GitHub](/guide/automation/github/)。

## 找到提交对应的线程

提交与线程的关联不改提交信息，按三种来源依次查找：

1. **线程推送**：出站代理记下线程经它的 `git push` 推了哪个 ref、从哪个提交到哪个提交；镜像拉到之后，展开成这次推送带来的提交，每次至多 500 个。
2. **线程里出现过**：线程运行时采样到的提交。
3. **经 PR 合并**：GitHub 项目打开提交详情、且前两种都没找到时，按「提交所属 PR → 最早关联这个 PR 的线程」反查一次，补上 squash 合并。没有线程的结果 24 小时内不再反查。

## 处理「仓库区块不可用」

仓库区块不可用时，主页只显示一条说明，「最近线程」与服务照常。

|说明|含义|
|---|---|
|还没有关联仓库|项目没有仓库地址，去设置「概览」填写|
|控制面未安装 git / git 版本过旧|控制面主机没有 git 或低于 2.31，仓库浏览停用，其余功能不受影响|
|仓库尚未克隆|已归档的项目不自动克隆，点「立即同步」|
|只支持 https:// 仓库地址|`git@…` 或带端口、用户名的地址不能镜像|
|需要凭据 / 凭据被拒绝|私有仓库没有可用令牌：连接 GitHub 账号或添加 `git/<主机>/token`；或令牌无权读这个仓库|
|找不到仓库 / 连不上仓库主机 / 拉取超时|上游 404、网络不通，或首次克隆超过 15 分钟、增量拉取超过 5 分钟|
|仓库主机解析到内网地址，已拦截|没有令牌的主机只能连公网地址|
|仓库超过镜像大小上限|镜像超过 `repos.max_mirror_gb`（缺省 5 GiB）：拉取中途被终止，或拉取完成后镜像被删除|
|控制面磁盘空间不足|数据盘可用空间低于 `repos.min_free_gb`（缺省 2 GiB），不克隆、不拉取|
|克隆中…|首次克隆可能需要几分钟，完成后自动刷新|
|仓库是空的|镜像就绪但还没有任何分支，推送第一个提交后显示|

`repos.*` 键由管理员在控制面配置里设置，见[仓库镜像与托管仓库入口](/admin/components/repos/)。

## 打开 Git LFS 文件

文件列表里 LFS 文件带「LFS」标记，大小是对象的真实大小。打开文件时控制面按需向仓库主机取对象，控制面主机不需要装 `git-lfs`。

- 取对象用与镜像拉取相同的凭据，而且只用仓库主机自己的 LFS 接口，不读仓库里的 `.lfsconfig`，令牌只发给它所属的主机。
- 取到的对象放进本地缓存，所有项目合计 `repos.max_lfs_cache_gb`（缺省 2 GiB），先清最久没用的。
- 超过 100 MiB 的对象不在浏览器里预览，只能下载。
- 取不到时文件页显示原因（对象不存在、凭据被拒、连不上存放对象的主机、内容与指针不符、磁盘空间不足）和「重试」。
- 提交的 diff 显示的是指针文本的改动。

## 限制

| 项 | 上限 |
|---|---|
| 自动拉取间隔 | 距上次拉取超过 60 秒才拉 |
| 首次克隆 / 增量拉取超时 | 15 分钟 / 5 分钟 |
| 镜像大小 | `repos.max_mirror_gb`，缺省 5 GiB |
| 数据盘最低可用空间 | `repos.min_free_gb`，缺省 2 GiB |
| LFS 缓存 | `repos.max_lfs_cache_gb`，缺省 2 GiB（所有项目合计） |
| 浏览器内预览的 LFS 对象 | 100 MiB |
| README 显示 | 512 KB，超过截断 |
| 单次推送展开的关联提交 | 500 个 |
