*本页回答：视图是什么、你的操作去了哪里？*

视图是 Agent 直接在对话里给出的可交互界面：表单、选项、KPI、表格、图表、示意图或小工具，而不只是文字。它是转录里的一次性回答，随对话走，不进 Artifacts 列表。要留存、迭代或发布的成品，Agent 仍做成 artifact（见 [Artifacts 概览](/guide/artifacts/overview/)）；回合里必须马上拿到的简单答案，Agent 仍用提问卡向你提问。

## 两种形态

| 形态 | 怎样构成 | 外观 |
|---|---|---|
| 声明式视图 | 用 Oryn 的组件拼装：标题、Markdown 正文、徽标、提示条、分隔线、KPI 行、属性表、表格、列表、进度条、图片、Chart.js 图表、SVG 示意图、表单、快捷回复按钮，外加卡片、分栏、标签页三种容器，最多嵌套 3 层 | 跟随应用主题 |
| 「HTML 视图」 | 模型写的 HTML，在独立源的沙箱帧里运行，可选离线注入 Tailwind 与 Chart.js | 主题变量与基础控件样式内置 |

视图直接出现在转录里，不套工具卡外壳，也不随批次折叠。内容还没生成出来时，先显示「正在生成视图」的占位。声明式视图在生成过程中逐块出现，控件在调用开始执行前保持禁用。HTML 视图在调用开始执行后才挂载，高度跟随内容、没有上限，内容不在帧内滚动；按视口撑满的页面（`100vh` 一类）停在 480 px。

<Shot id="site/view-actions" alt="一个视图里画着「已连接 → 退避等待 → 补拉中」的重连状态机示意图，下方是「就按这个改」「先只做 Web」「再想想」三个快捷回复按钮" />

## 你的操作去了哪里

表单提交、按钮点击，以及 HTML 视图里页面调用的 `window.oryn.sendPrompt(text)`，都回到 Agent。回到 Agent 的方式有两种，由模型对每次调用决定：

- **作为你的下一条消息（缺省）。** 转录里出现一个带「来自视图」小标的普通消息气泡，Agent 在下一回合读到它。
- **作为这次调用的结果。** 模型给调用设了 `await: true` 时，调用挂起等你作答，线程显示为等你处理并发出推送。你的作答成为这次调用的结果，Agent 在同一回合里接着做。10 分钟没人作答时，调用照常返回，视图仍可操作，之后的作答作为消息到达。你改为在输入框里打字时，挂起的调用立刻结束，按改用文字回复处理。

视图是一回合最后要说的话时，模型可以设 `endTurn: true`：工具跑完回合直接结束，不再为一句收尾话多请求一次模型。真正挂起等作答的调用忽略这个设置。

## 用过即锁

每个表单、每组按钮只能作答一次，之后锁定并显示已提交的内容。HTML 视图每次调用只回传一次。锁定状态从转录推导，换一台设备打开也一样。

## 谁能用

| 能用视图 | 不能用视图 |
|---|---|
| 工作线程的主 Agent（执行环境（orb）里的线程与 Runner 上的线程）、全局助手 | 子 Agent、Space 协调者、研究员、受限主线 |

全局助手的 `await` 是尽力而为：挂起中的调用只保存在控制面的内存里，控制面重启后不保证还在。

## 开关

视图由「设置 → 扩展与工具」里的「生成式 UI」控制，缺省开启。关闭后：

- 新启动的 Agent 不注册视图工具，系统提示里也没有视图的指引。工作线程在下次 Agent 启动时生效，助手对话在静止后重启时生效。
- 已有的视图照常显示。

开启时，视图的两个工具连同指引约 4.7k token，每个请求都带（走提示缓存）。

## 在公开分享页里

线程的公开分享页里，声明式视图照常显示，控件禁用；HTML 视图照常运行，但回传无效。撤销分享后，帧随即失效。分享见[公开分享线程](/guide/threads/sharing/)。

## HTML 视图的边界

HTML 视图的帧在不透明源里，`connect-src 'none'`、`form-action 'none'`，读不到父页面与你的登录态。但它可以从任意 `https` 主机加载脚本、样式、字体、图片与媒体：对方能看到访问者的 IP 与 UA，URL 里也可以带上模型写入的数据。全局助手关闭联网时，这仍是一条出站路径。

## 自建 Anthropic 兼容网关时的逐块显示

声明式视图要逐块出现，模型 API 必须边写边发工具参数。Anthropic 默认把每个参数值写完才发出，而视图的全部内容都在一个参数 `blocks` 里，于是整块一次到达。Oryn Core 只对官方 API 自动打开边写边发。

模型走自建的 Anthropic 兼容网关时，在 `models.yml` 里该 provider 的 `compat` 下加一行，网关须透传工具上的 `eager_input_streaming` 字段：

```yaml
# models.yml 中该 provider 的配置下
compat:
  supportsEagerToolInputStreaming: true
```

改完在设置里重启受影响的会话。模型配置见[模型与密钥](/guide/agent/models-and-keys/)。
