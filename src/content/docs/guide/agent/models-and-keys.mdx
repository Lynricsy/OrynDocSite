Agent 用到的模型、供应商与 API Key 写在 omp 配置目录里（本机通常是 `~/.omp/agent`，其中模型定义在 `models.yml`）。控制面保存一份全局 omp 配置并下发到每台执行环境（orb）；第一次部署后、以及本机配置有变化时，你要把它上传一次。

## 上传本机的 omp 配置

在已用 `oryn login` 登录控制面的电脑上运行（登录方法见[命令行 oryn](/guide/clients/cli/)）：

```bash
oryn config push ~/.omp/agent
```

这条命令打包上传整个目录，整体替换控制面上的全局 omp 配置。目录参数省略时默认就是 `~/.omp/agent`。

- 自动排除：`sessions/` `blobs/` `cache/` `logs/` `natives/` `terminal-sessions/` `*.db` `*.db-*` `auth.json` `history*`。
- `models.yml` 里的字面 `apiKey` 由控制面抽进密钥库，存下的配置里只留引用；其它文件原样保存，其中形似密钥的字符串只给出警告。
- 只上传普通文件：设备、FIFO、socket 会直接报错，可用 `--exclude` 排除。`rules/` 下的文件与 `*.md` `*.yml` `*.yaml` `*.json` 必须是 UTF-8 文本。
- 全局推送会跟随目录里的符号链接（包括指向目录之外的目录），悬空链接与指向被排除路径的链接跳过并提示。

上传成功后，环境里拿到的只有占位令牌，真实 Key 留在控制面。

<Aside type="caution" title="备份主密钥">
密钥库用控制面数据目录下的 `master.key` 加密（`data_dir/master.key`，控制面首次启动时生成）。丢失这个文件，库里的 API Key 与令牌都无法解密。备份方法见[备份](/admin/operations/backup/)。
</Aside>

## 排除不想上传的文件

有两种方式，可以同时使用：

- 命令行加 `--exclude <glob>`，可重复。
- 在要上传的目录里放一个 `.orynignore`，每行一个 glob，`#` 开头为注释。

glob 按相对路径匹配，匹配到目录即排除整个目录，例如 `extensions/omp-notify`、`omp-notify*`。

```bash
oryn config push ~/.omp/agent --exclude 'extensions/omp-notify'
```

## 在网页上直接编辑配置文件

「设置 → 助手与 Agent → 配置文件」是全局 omp 配置的文件浏览器与编辑器。在这里保存 `models.yml` 时，其中的明文 API key 同样自动抽进密钥库，页面列出「已抽取进密钥库」的条目。`config.yml` 是例外：它除了下发到环境，也下发给全局助手。

技能、规则、角色等常用内容有表单页，见[技能、规则与指令](/guide/agent/instructions/)与[模型角色与思考档位](/guide/agent/roles/)。

## 把配置下载回本机

```bash
oryn config pull
```

逐个下载文件到目录（默认 `~/.omp/agent`），按服务端记录的权限写入，不删除本地多出的文件。

- 服务端的 `models.yml` 是模板，密钥已替换为 `${oryn:secret:…}` 引用。下载时默认写成 `models.oryn.yml`，不覆盖你本地带真实密钥的 `models.yml`。
- 加 `--force` 时直接覆盖 `models.yml`，其中只有密钥引用，没有真实值。
- 加 `--dry-run` 只列出将写入的文件。
- 父目录经符号链接指向目标目录之外，或要写的文件本身是符号链接时，命令拒绝写入；先删除该链接。

## 选择密钥的注入方式

密钥库里的每个密钥有两种模式：

| 模式 | 值在哪里 | 环境里看到什么 |
|---|---|---|
| `proxy`（默认） | 留在控制面，由出站代理在请求时注入 | 只有 `oryn-ph-…` 占位符 |
| `env` | 以同名环境变量注入 Agent 进程 | 真实值 |

`proxy` 模式下，请求经环境里 `orbd` 的本地端口回到控制面，控制面按密钥绑定的上游主机注入真实值，并把响应里回显的凭据脱敏回占位符。只有显式设为 `env` 的自定义密钥，或没有绑定上游主机的模型 Key，才会以环境变量下发。机制细节见[凭据隔离与出站代理](/security/credentials/)。

在「设置 → 工作区 → 密钥」里管理密钥，或用命令行：

```bash
# proxy 模式：只允许注入到列出的上游主机
oryn secrets set <密钥名> --hosts <主机1>,<主机2>

# env 模式：名称须匹配 [A-Z_][A-Z0-9_]*
oryn secrets set <变量名> --mode env

oryn secrets ls
oryn secrets rm <密钥名>
```

省略值时，`oryn secrets set` 从标准输入读取。密钥的值只写不读。git 主机令牌命名为 `git/<主机>/token`。模型供应商密钥只能全局设置；项目级的环境变量与 Git 令牌见[密钥与环境变量](/guide/projects/secrets/)。

## 模型 Key 的绑定规则

`models.yml` 里引用密钥时，控制面按下面的规则校验：

- `providers.<key>.apiKey` 只能引用本 provider 自己的密钥 `omp/models/<key>/apiKey`。
- 只有这一个密钥可以降级为环境变量；它若已绑定上游主机（`hosts` 非空），就不允许降级。
- `models.yml` 里不允许引用 `git/*` 密钥。
- 其它 `${oryn:secret:…}` 引用必须属于 `hosts` 非空的密钥，而且只注入到 origin 主机与 `hosts` 匹配的路由。
- `hosts` 为空的密钥只能注入到它自己 provider 的路由。
- 导入时，provider 密钥的 `hosts` 包括 provider `baseUrl` 与各模型 `baseUrl` 的全部主机。

## 刷新模型目录

设置页、首屏与线程里的模型列表来自同一份模型目录：控制面用钉定版本的 Oryn Core 运行一次 `omp models` 生成，包含 `models.yml` 里的自定义 provider 与有密钥的内置 provider，以及各模型的思考档位和自带的默认档位。查看模型列表不需要打开线程或唤醒环境。

配置变化后目录自动重算；目录 24 小时过期，也可以手动刷新。

## 限制

- 模型目录 24 小时过期。
