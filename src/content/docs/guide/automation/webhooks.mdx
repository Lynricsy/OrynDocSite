入站 Webhook 是项目级定时（「每次新建线程」）上的一个公开调用地址。外部系统——CI、监控告警、表单、别家服务的 webhook——向它 POST 一次，就触发一次运行，运行记录里的触发方式为 `webhook`。它常与 `--manual` 搭配：这种定时没有时间触发、没有下次运行时间，只由手动触发（`oryn schedule run`）或 Webhook 触发。定时本身怎样建见[定时任务](/guide/automation/schedules/)。

## 开启 Webhook

在网页端定时的编辑对话框里，「入站 Webhook」一节点「开启 Webhook」。

等价命令：

```bash
oryn schedule webhook <定时 id>
```

首次开启时生成调用地址，形如 `https://oryn.example.com/api/v1/public/hooks/owh_…`。地址**只显示这一次**：控制面只存它的哈希，之后取不回，丢了只能换新。命令行把新地址单独一行打印到标准输出；加 `--json` 时以 JSON 输出（含这一次的 `url`）。

只有你本人能开启与换新，全局助手的 `oryn` 工具调不了。

## 换新或关闭地址

- **换新**：界面里点「换新地址」，或 `oryn schedule webhook <定时 id> --rotate`。旧地址立即失效，调用方须改用新地址。
- **关闭**：界面里点「关闭」，或 `oryn schedule webhook rm <定时 id>`。地址立即失效；没开过也算成功。

## 设置签名

签名是可选的。不设签名时，拿到地址的人都能触发这个定时。

```bash
# 从标准输入读取签名密钥，避免留在 shell 历史里
printf '%s' "<签名密钥>" | oryn schedule webhook <定时 id> --secret-stdin
# 去掉签名
oryn schedule webhook <定时 id> --clear-secret
```

签名密钥至多 256 个字符。`--secret-stdin` 与 `--clear-secret` 都不给时保留原值。界面里对应「设置签名密钥」「更换签名密钥」「去掉签名」。

设了签名密钥后，调用方必须带 `X-Oryn-Signature-256` 请求头（也认 GitHub 风格的 `X-Hub-Signature-256`），值为：

```text
sha256=<hex(HMAC-SHA256(密钥, 原始请求体))>
```

## 调用地址

请求体是任意 UTF-8 文本，至多 64 KiB。下面的示例中 `SECRET` 是签名密钥：

```bash
URL='https://oryn.example.com/api/v1/public/hooks/owh_…'
BODY='{"alert":"db-1 磁盘使用率 95%"}'
# 设了签名密钥时：对原始请求体算 HMAC-SHA256（没设签名密钥则去掉下面的 X-Oryn-Signature-256 头）
SIG=$(printf '%s' "$BODY" | openssl dgst -sha256 -hmac "$SECRET" | awk '{print $NF}')
curl -sS "$URL?source=grafana" \
  -H 'Content-Type: application/json' \
  -H "X-Oryn-Signature-256: sha256=$SIG" \
  --data-binary "$BODY"
```

请求体连同 `User-Agent`、名称含 `Event` / `Delivery` 的请求头（签名与凭据类的头不记）和查询参数，作为不可信数据块 `<untrusted-webhook-content>` 接在定时的提示词之后交给新线程。同样的内容记在这次运行的记录里（`payload`），可以在运行列表里点「查看收到的请求」查看。

运行前闸门对 Webhook 触发同样生效，但请求内容不交给闸门。上一次运行还没结束时按定时的 `overlap` 处理。

## 响应码

| 情况 | 状态码 | 说明 |
|---|---|---|
| 受理 | 202 | 带本次运行的 `runId` 与 `status` |
| 上一次运行还没结束（按定时的 `overlap` 跳过） | 202 | 仍记一条跳过的运行，`status = skipped` |
| 地址无效 | 404 | |
| 签名缺失或不符 | 401 | `bad_signature` |
| 定时已暂停 | 409 | `schedule_paused` |
| 项目已归档 | 409 | `project_archived` |
| 请求体超过 64 KiB | 413 | |
| 请求体不是 UTF-8 | 400 | |
| 同一来源 IP 调用过于频繁 | 429 | `rate_limited` |

## 了解 Webhook 运行的限制

Webhook 触发的运行按不可信输入处理。同一定时按时与手动触发的运行不受这些限制。

- 建出的线程一律是全自动线程，并标为不可信。
- GitHub 只用 Agent 账号。Agent 账号未连接或需要重新授权时，这次运行失败（`github_agent_required`），不回退到你的账号。见 [GitHub：仓库绑定、PR 与回流](/guide/automation/github/)。
- SSH 只能用允许全自动线程使用的主机。见 [SSH 主机](/guide/automation/ssh-hosts/)。
- 开着「交给助手」时，结果只交给[主线](/guide/assistant/mainline/)受限的一轮：只能读、能 `stay_silent`。

<Aside type="caution">
项目级密钥与环境变量照常注入该项目的线程：能调用这个地址的人，就能把内容送到一个拿得到这些值的 Agent 面前。处理外部输入的定时放在不带敏感密钥的项目里。签名、数据块标签与运行前闸门只决定谁能触发、要不要运行，不能代替上面这些凭据与权限限制。
</Aside>

## 限制

| 项 | 值 |
|---|---|
| 请求体 | 至多 64 KiB，UTF-8 |
| 签名密钥 | 至多 256 字符 |
| 可开 Webhook 的定时 | 只限项目级定时（每次新建线程） |
