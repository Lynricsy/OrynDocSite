后台研究让全局助手在你没问的时候自己去看新信息：跟进你问过的问题与关心的主题，翻看线程找出跨线程的矛盾与卡住，用你勾选的 MCP 只读工具查邮件与日历。有值得说的才在[主线](/guide/assistant/mainline/)里说，每日花费有硬上限。

<Requires ids={['assistant-network']} />

## 打开后台研究

在「设置 → 全局助手 → 后台研究」打开「开启后台研究」。总开关缺省关闭。同一张卡片上还有：

- 四条管线各自的开关，见下一节。
- 「研究员的模型」：研究员用的模型。
- 「每日花费上限（美元）」：缺省 20 美元，可设 0.1–1000。
- 「研究偏好」：交给研究员的一段说明。

<Shot id="site/research-settings" alt="后台研究设置卡片：「开启后台研究」总开关与四条管线的开关，下方是研究员的模型、每日花费上限（美元）与研究偏好输入框" />

## 了解四条管线

| 管线 | 节奏 | 做什么 |
|---|---|---|
| 「公网话题跟进」 | 话题登记 24 小时后第一次查；没有新东西时间隔翻倍，最长 7 天；有新发现时回到 24 小时 | 研究员搜索、读公网网页，查跟进清单里的话题。主线助手拿发现对照当时的回答，回答过时或有误就主动更正 |
| 「从助手对话与主线里自动挖掘要跟进的话题」 | 助手对话与主线静止 30 分钟、且有你的新消息时 | 从对话里挑出值得跟进的话题，自动登记进跟进清单 |
| 「内部关联：跨线程的矛盾、重复与卡住」 | 工作线程有新消息时，至多每 2 小时一次；没有新消息就不调用模型 | 一个不能上网的研究员翻看线程，报告跨线程的矛盾、重复与卡住 |
| 「MCP 检查：用勾选的只读工具看邮件、日历等」 | 每 60 分钟 | 用你勾选为研究可用的 MCP 工具查看新内容，报告需要你处理的事项 |

助手的「允许助手联网」关着时，公网话题跟进不运行。

## 选择 MCP 检查可用的工具

MCP 检查只用你逐个勾选的工具，缺省一个都不勾。在 MCP 服务器卡片上点「研究可用工具」，在对话框里勾选：

- 对话框以 Streamable HTTP 连上服务器列出工具，超时 20 秒。SSE 服务器列不出工具，改为在「工具名（每行一个）」里手填。
- 「自报只读」取自服务器自己的标注，是服务器的说法，不是保证，所以对话框不预先勾选任何工具。
- 在助手设置里关掉的 MCP 服务器，研究同样用不了。

<Aside type="caution">
只勾不会对外发送数据、不会改动任何东西的读取工具。邮件的「发送」、日历的「创建」一旦勾上，网页或邮件里的注入就能借研究员调用它们。
</Aside>

## 管理跟进清单

点主线页头的「跟进」打开清单，可以新建、编辑、暂停、删除和立即检查话题。话题有两种：

| 种类 | 基线 | 何时结束 |
|---|---|---|
| 「问题跟进」 | 带当时的回答作基线 | 30 天后结束 |
| 「长期关注」 | — | 不结束 |

新建时填「种类」「标题」与「要查什么」。公网研究员拿到的只有话题的种类、标题、问题、上一次的报告与当天日期，看不到你的对话和当时的回答，所以「要查什么」只写要查的公开信息。

<Shot id="site/follow-ups" alt="「跟进」对话框：上方是新建表单（种类、标题、要查什么），下方三条话题各带种类、来源、下次检查时间与上次发现，行内有暂停开关" />

自动挖掘登记的话题不逐条请你确认，你在清单里改或删。删掉的话题不会再被同名登记。

## 在工作线程里登记跟进

在工作线程里让 Agent「跟进这个」，Agent 会在环境内执行：

```bash
oryn follow add --title "<一句话标题>" --question "<要查的公开信息>" --quote "<你在本线程里让它跟进的原话>"
```

控制面核对 `--quote` 的原话确实出现在该线程里你发的消息中，否则拒绝登记。`--kind` 取 `question`（问题跟进，缺省）或 `interest`（长期关注）。这样登记的话题有结果时只进主线，并注明来自哪个线程。完整参数见 [`oryn follow`](/reference/cli/follow/)。

## 查看发现

发现在主线里折叠成「幕后 · 后台研究」，展开能看到标题、摘要、来源链接与关联的线程。

来自网页、邮件、日历的发现，只交给一轮工具受限的主线处理：这一轮只能读、能保持沉默，不能开线程、发消息、用电脑、联网或改任何东西，也不能改备忘。你恰好在这一轮里发来的消息也由受限的助手回答。这一轮结束后主线恢复全部能力；想让它动手，回一句即可。内部关联的发现照常交给完整的主线。

研究员拿到哪些数据、受限的一轮为什么这样设计，见[协调沙箱与不可信输入](/security/sandbox-untrusted/)。

## 控制花费

研究员对话的模型用量照常记进[统计](/guide/automation/stats/)。当天（本地时区）合计达到每日上限后，当天不再发起研究，并发一条预算通知，每天至多一条。

## 限制

| 项 | 上限 |
|---|---|
| 每日花费上限 | 缺省 20 美元，可设 0.1–1000 |
| 公网话题跟进的检查间隔 | 24 小时起，最长 7 天 |
| 自动挖掘 | 每个对话每次至多 3 个话题；带网址或 `@` 的不登记 |
| 活跃话题 | 50 个 |
| 「问题跟进」的有效期 | 30 天 |
| 内部关联 | 至多每 2 小时一次，每次至多 3 条 |
| MCP 检查 | 每 60 分钟一次，每次至多 5 条 |
