Firecracker 驱动把每个执行环境（orb）做成一台 microVM：独立内核、独立的根文件系统写层、每台 VM 一条 /30 点对点 tap。隔离强于容器，代价是 Provider 必须以 root 运行，宿主要有 KVM。各后端的取舍见[选择执行后端](/guide/environments/backends/)。

## 确认宿主满足前提

- x86_64 宿主，`/dev/kvm` 与 `/dev/net/tun` 可用（在虚拟机里跑需要开嵌套虚拟化），cgroup v2，`ip`、`nft`、`mke2fs`、`cp` 在 `PATH` 里。
- Firecracker 官方支持的宿主内核是 5.10 / 6.1 / 6.18，其它版本预检只给警告。
- 状态目录与产物必须在同一个文件系统上（基础盘用硬链接）。

## 构建并安装产物

在 Oryn 源码根目录执行：

```bash
make image                 # 根盘取自 orb 镜像（FC_IMAGE，默认 oryn-orb:dev）
make fc-artifacts          # build/fc/{firecracker,jailer,vmlinux,rootfs.ext4}；不需要 root，内核构建约 2 分钟
sudo install -D -m 755 build/fc/firecracker build/fc/jailer -t /usr/local/bin/
sudo install -D -m 644 build/fc/vmlinux build/fc/rootfs.ext4 -t /var/lib/oryn-fc/artifacts/
```

Firecracker 与内核源码的版本和 sha256、构建用的容器镜像 digest 都锁定在 `images/fc/artifacts.lock.json`，构建脚本拒绝没带 digest 的镜像引用。

<Aside type="caution">
更新根盘要用 `install` 换成新文件，不能原地覆盖：运行中 VM 的基础盘是它的硬链接，原地写会改坏这些 VM。
</Aside>

换了根盘或内核后，Provider 上报的基础镜像身份随之变化，旧的项目快照全部失效。

## 建立宿主网络

```bash
sudo install -D -m 755 deploy/firecracker/oryn-fc-net.sh /usr/local/lib/oryn/oryn-fc-net.sh
sudo install -m 644 deploy/systemd/oryn-fc-net.service /etc/systemd/system/
sudo systemctl enable --now oryn-fc-net
```

`oryn-fc-net.sh up` 做以下几件事：

- 建一个 dummy 接口 `oryn-fc`（地址 `172.31.255.1/32`），控制面在这个地址上给 guest 提供 link；打开 `ip_forward`。
- 装两张 nft 表 `inet oryn_fc` 与 `ip oryn_fc_nat`：
  - guest 发往宿主的流量，只放行到 `172.31.255.1` 的 `ORYN_FC_LINK_PORTS` 端口（默认 `7643`）。
  - guest 之间、guest 到私有网段 / 链路本地 / 环回一律丢弃，出网走 masquerade。
  - 从 `fc-*` 进来、源地址不在网段内或反向路径查不到本接口的包直接丢弃，不依赖 sysctl（宿主 `rp_filter` 设成宽松也照样生效）；`fc-*` 的 IPv6 进出一律丢弃。
- 宿主有 Docker 时，在 `DOCKER-USER` 里追加两条放行，否则 Docker 的 FORWARD 默认丢弃会拦掉 guest 出网。

每台 VM 的 tap 由 Provider 建（`/30`、严格反向路径过滤），VM 之间没有共享二层。

脚本的三个子命令与环境变量：

| 用法 | 作用 |
|---|---|
| `oryn-fc-net.sh up` | 建接口、开转发、装规则；幂等，可重复执行 |
| `oryn-fc-net.sh down` | 删掉 nft 表、`DOCKER-USER` 规则与 `oryn-fc` 接口（`ip_forward` 不动） |
| `oryn-fc-net.sh rules` | 只打印要装的 nft 规则，不改宿主；`oryn-fc-net.sh rules \| nft -c -f -` 可校验规则 |

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `ORYN_FC_CIDR` | `172.31.0.0/16` | guest 网段，与 `firecracker.network.cidr` 保持一致 |
| `ORYN_FC_HOST_ADDR` | `172.31.255.1` | 控制面在 guest 侧监听的地址，与 `firecracker.network.host_addr` 保持一致 |
| `ORYN_FC_LINK_PORTS` | `7643` | guest 可以连到上面地址的 TCP 端口，逗号或空格分隔 |

`oryn-fc-net.service` 用 `Environment=` 设置这三个变量，排在 `docker.service` 之后、`orynd.service` 与 `oryn-provider-fc.service` 之前：控制面要监听 `172.31.255.1`，这个地址必须先于控制面存在。

## 写出配置

控制面给 guest 开 TLS 的 link 监听，Provider 使用单独的配置文件 `/etc/oryn/provider-fc.yaml`：

```yaml
# orynd.yaml：给 guest 开 TLS 的 link 监听
orb_tls: { listen: ["172.17.0.1:7643", "172.31.255.1:7643"] }

# /etc/oryn/provider-fc.yaml
url: "https://oryn.example.com"
token_file: "/etc/oryn/provider-fc.token"
orb_url: "https://172.31.255.1:7643"
driver: firecracker
firecracker:
  disk_gb: 40                                  # 每台 VM 的可写盘（稀疏文件，按实际写入占空间）
  # uid_base: 2000000000                       # 槽位 n 的 jailer uid/gid = uid_base + n；须避开 subuid/subgid 与已有用户
  limits: { max_vms: 8, max_memory_mb: 32768 } # 超出时 spawn 失败，原因 capacity
  types: { small: {cpus: 2, memory: "4g"}, medium: {cpus: 4, memory: "8g"}, large: {cpus: 8, memory: "16g"} }
  default_type: medium
```

`token_file` 里的令牌用 `oryn provider create` 取得：在已 `oryn login` 的机器上执行，标准输出只有令牌，只显示这一次。

```bash
oryn provider create fc | sudo tee /etc/oryn/provider-fc.token >/dev/null   # fc 是 Provider 名称，可自定
sudo chmod 0600 /etc/oryn/provider-fc.token
```

没开 `orb_tls` 的部署：`orb_url` 写 `http://172.31.255.1:7600`，`orynd.yaml` 的 `listen` 加 `172.31.255.1:7600`，并把 `oryn-fc-net.service` 的 `ORYN_FC_LINK_PORTS` 改成 `7600`（或两个都写 `7600,7643`）。

二进制、内核、根盘与状态目录的路径，网段、DNS 与规格表的全部键见 [`provider.yaml` 配置参考](/reference/config/provider-yaml/#firecracker)。

## 预检并启动

```bash
sudo oryn provider preflight --config /etc/oryn/provider-fc.yaml   # 逐项打印检查结果，全过再启动
sudo install -m 644 deploy/systemd/oryn-provider-fc.service /etc/systemd/system/
sudo systemctl enable --now oryn-provider-fc
```

`oryn provider preflight` 核对：

- 以 root 运行，KVM、tun、cgroup v2 可用。
- 产物与状态目录在同一个文件系统上。
- `oryn-fc` 接口与 nft 表存在，`orb_url` 的端口在放行列表里。
- 网段不与宿主其它接口重叠。
- 槽位 uid/gid 区间 `[uid_base, uid_base+16320)` 不与 `/etc/subuid`、`/etc/subgid` 的任何一段及已有用户 / 组重叠。重叠时列出冲突并建议一个空闲的 `uid_base`：持有重叠 subuid 的本机用户能在自己的 user namespace 里变成槽位 uid，向 jail 里的 firecracker 发信号。

全部通过时退出码为 0，有检查项失败或配置出错时为 1。

`oryn-provider-fc.service` 以 root 运行 `oryn provider run --config /etc/oryn/provider-fc.yaml`，依赖 `oryn-fc-net.service`。Provider 停止或重启不会连带杀掉 VM：jailer 把 firecracker 移进 `/sys/fs/cgroup/oryn-fc/` 下各自的 cgroup，不在本服务的 cgroup 里；重启后驱动按状态目录（`state_dir`）接管已有 VM。

## 了解与 Docker 驱动的行为差异

| 方面 | Firecracker 驱动的行为 |
|---|---|
| 冻结 | 只停 vCPU，内存仍留在宿主进程里，与 `docker pause` 一样占内存；`limits.max_memory_mb` 把冻结的 VM 也算在内 |
| 停机 | 向 guest 发关机请求，30 秒内不退出就强杀；磁盘和槽位保留，下次唤醒重新开机 |
| 项目快照 | 可写盘的稀疏复制（文件系统支持时用 reflink）；运行中的 VM 拍快照时先在 guest 里冻结文件系统、暂停 VM、复制、再恢复，前后不到几秒 |
| 令牌与密钥 | guest 里的 `orbd` 作为 PID 1 启动，时间、主机名、DNS 和令牌经 vsock 下发；模型与 git 的密钥不进 VM。令牌只放在 guest 的 tmpfs `/run/oryn/orb-token`（`$HOME/.oryn/orb-token` 是指向它的链接），可写盘和由它复制出的快照里没有令牌；发布快照或 fork 之后，控制面还会给源环境换一次令牌 |
| 串口日志 | 写在每台 VM jail 里的 4 MiB tmpfs 上（jail 根目录下的 `console/console.log`），写满后丢弃后续字节、guest 照常运行；Provider 在跑时每 30 秒把超过 2 MiB 的日志裁到最后 512 KiB，失败任务里带的串口尾部取自这里 |
| 拍快照中途出错 | 冻结 guest 文件系统前留一个 `thaw-pending` 标记，VM 恢复全部成功才删掉；恢复失败时快照任务失败、不发布。下一次对这台 VM 的 spawn、冻结或快照会先把它恢复好 |
| Provider 崩溃 | VM 已开机、guest 还没收到启动参数时崩溃，重启后的 spawn 会补发完整的启动请求，不会留下一台没有 `orbd` 的 VM |
| 停机预览 | 在用户态解析 VM 的基础盘与可写盘（不挂载），文件面板可只读浏览停机的环境 |

## 限制

| 项 | 值 |
|---|---|
| 每台 VM 的可写盘 | `firecracker.disk_gb`，示例与缺省均为 40 GB |
| VM 数上限 | `firecracker.limits.max_vms`，缺省 8；超出时创建失败，原因 `capacity` |
| 全部 VM 的内存合计 | `firecracker.limits.max_memory_mb`，缺省 32768 MiB，冻结的 VM 也算在内 |
| 槽位 uid/gid 区间 | `[uid_base, uid_base+16320)` |
| 停机等待 | 30 秒后强杀 |
| 串口日志 | 4 MiB tmpfs；超过 2 MiB 时裁到最后 512 KiB |
