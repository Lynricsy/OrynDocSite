## 各方的凭据

浏览器、客户端、Provider、执行环境（orb）与 Runner 连到控制面时，各用下表里的凭据证明身份。

| 谁 | 凭据 | 说明 |
|---|---|---|
| 浏览器 | 会话 Cookie `__Host-oryn_session` | 变更类请求另需请求头 `X-Oryn-CSRF: 1` |
| 首次初始化 | 初始化令牌 `ost_…` | 控制面首次启动、还没有所有者时打印在 setup 链接里。令牌在 URL 片段里，不会进入反代访问日志；链接丢失时用 `orynd setup-token` 重新生成 |
| 已配对设备 | 设备令牌 `odt_…`，以 `Authorization: Bearer odt_…` 发送 | 桌面与移动客户端里，设备令牌只驻留在客户端进程与系统凭据库（macOS 钥匙串、Windows 凭据管理器、Linux Secret Service、Android Keystore），网页脚本读不到。你在自己电脑上经 `/git/` 访问托管仓库时只认设备令牌 |
| Provider | Provider 令牌 `opv_…` | 用于 Provider 协议 |
| 执行环境 | 环境令牌 `oot_…` | 环境里的守护进程 `orbd` 凭它连回控制面，见下一节 |
| Runner | Runner 令牌 `ort_…` | 只用于 `/orb/v1/link` 与 `/orb/v1/whoami`。控制面只存它的哈希；在「设置 → Runner」里删除 Runner 即吊销，已连着的连接会被断开 |
| 入站 Webhook 调用方 | 地址里的 `owh_…` | 控制面只存它的哈希，之后取不回，丢了只能换新 |

设备的配对与吊销见[浏览器：登录、设备与外观](/guide/clients/web/)；全部前缀见[术语表](/reference/glossary/)。

## 环境令牌的轮换

环境令牌由 `HMAC(密钥, 环境 ID : 代数)` 派生。每次控制面让 Provider 拉起环境（创建、唤醒，以及冻结的环境转为停机前的解冻）都会换一个新令牌，旧令牌立即失效，现有连接同时被关闭。给环境拍快照（发布项目快照、连环境分叉）之后也会轮换一次，快照里残留的令牌随即作废，快照磁盘内不留有效令牌；Firecracker 环境的令牌只驻留在内存 `tmpfs` 里。

控制面只在环境处于 `spawning`、`connecting`、`setting_up`、`resuming`、`ready`、`waking` 或 `stopping` 状态时接受它的连接；`frozen`、`stopped`、`failed`、`deleting`、`deleted` 一律拒绝。唤醒只能由 Provider 驱动，所以泄露的令牌既不能把一台冻结或停机的环境拉起来，也活不过它的下一次唤醒。

新令牌的送达方式：新建的机器经环境变量 `ORYN_ORB_TOKEN`；已存在的机器写入 `$HOME/.oryn/orb-token`，再向 `orbd` 发 `SIGHUP` 让它立即重连。用脚本接入其它后端时，脚本必须自己完成这一步，契约见[用脚本接入其它后端](/admin/backends/dispatch/)。

## Runner：单向信任

Runner 把你自己的机器接入为线程的执行位置。它与控制面之间的信任只有一个方向：Runner 完全信任控制面，控制面的密钥不去 Runner。安装与启动见[在自己的机器上跑线程](/guide/environments/runner/)。

### Runner 信任控制面

<Aside type="caution">
能操作控制面的人（网页会话、设备令牌，或攻破了控制面的人）都能以 Runner 进程的系统用户在那台机器上执行任意命令。Agent 本身不受目录限制，`--dir` 约束的只是面板能看到什么、线程能选什么。
</Aside>

因此只在你信任控制面的机器上运行 Runner，并用一个权限有限的普通用户运行它。`orbd` 以 root 运行时会直接拒绝（加 `--allow-root` 才放行）；`ORYN_URL` 是非回环的 `http://` 地址时会告警，应改用 HTTPS。

### 控制面不把密钥交给 Runner

- **配置不含密钥**：下发给 Runner 的全局与项目层 Agent 配置里，模型 Key 一律换成 `oryn-ph-…` 占位符，地址改写到本机的出站通道；`env` 模式的密钥不下发；需要以环境变量降级下发真实 Key 的模型供应商（没有 `baseUrl`）在 Runner 上不可用。下发前，控制面扫描每个文本文件里形似密钥的串，并比对长度 ≥ 8 的已知密钥明文（密钥库的全部值与密码登录 SSH 主机的密码）；命中的文件扣下不发，并在该 Runner 的事件里写明原因。
- **出站只放行模型中转与记忆**：Runner 在 `127.0.0.1:7811`（可用 `ORYN_EGRESS_ADDR` 改）常驻一条本地出站通道，控制面只放行模型中转 `/llm/` 与记忆网关 `/memory/`，由控制面注入真实的模型 Key 与 Hindsight Key，响应里的回显同步脱敏；其余路径一律 403。控制了这台机器的进程因此可以经中转调用中央模型（消耗额度），或访问该 Runner 线程所属项目的记忆，但拿不到任何密钥明文。
- **GitHub 与 git 凭据不下发**：控制面不往 Runner 下发 GitHub OAuth 凭据、git 主机令牌、git 代理改写或提交身份，也不改那台机器的 git 配置；Runner 上的 git 操作使用本机自己的凭据。
- **连接只受理少数请求**：Runner 的连接只受理转录同步、artifact 工具调用（只看得到自己建过或写过的 artifact）、文件库存入（只收线程工作目录内的普通文件）和状态通知，其余请求一律回 `runner_unsupported`，Runner 无法借别的线程把密钥绕回来。
- **SSH 每线程一把临时密钥**：Oryn 登记的 SSH 主机私钥和密码留在控制面，Runner 上的 `orbd` 在 `127.0.0.1:7822` 监听并把连接转给控制面的网关。`orbd` 为每个线程生成一把临时 ed25519 密钥，网关按认出的线程及其所属项目放行主机并记审计。局限是同一系统用户下的任何本机进程都能读到其它线程的私钥文件：这把密钥防的是某个线程的 Agent 误用别的项目的主机，不防恶意的本机进程。

Runner 上的面板也按声明收窄：文件面板与改动面板只能看到线程工作目录里的内容，线程目录必须落在 `--dir` 声明的目录里（或 Oryn 在它旁边建的 worktree），终端只有带 `--terminal` 才开。Runner 上没有 Portal、受管服务、远程桌面、`oryn sync`、项目快照，不能冻结、删除或连环境分叉，也不能绑定浏览器 Profile。

## 谁能操控 Runner 线程

除了你自己，只有全局助手。它可以像你一样在 Runner 上新建线程（指定目录、worktree 或共用目录），给 Runner 线程发消息、读取、归档、中止、改模型、分叉（只能共用环境）、设线程内定时，读写线程目录里的文件、查看改动；删除要你点确认卡。

Space 协调者与环境里的 Agent 禁止读写或操控任何 Runner 线程：协调者对 Runner 线程的发消息、读取、归档、定时等工具一律回 `runner_unsupported`，环境里的 Agent 只能联系自己的父子线程。普通环境里产出的内容因此不能经它们变成你机器上的指令。

全局助手会读网页与工作线程的输出，注入的指令有可能经它到达 Runner 线程，见[协调沙箱与不可信输入](/security/sandbox-untrusted/)。
