_本页回答：环境里的 Agent 能读写哪些仓库？_

执行环境（orb）里的 git 请求都经出站代理回到控制面，令牌由代理注入（机制见[凭据隔离与出站代理](/security/credentials/)）。代理按环境所属项目和目标主机决定放行范围，下面四种情形规则各不相同。

## github.com

环境由 GitHub 集成下发凭据时，github.com 的请求由出站代理注入线程所用身份（「我的账号」或「Agent 账号」）的 OAuth 令牌，不按项目仓库限制：环境能读写哪些仓库，取决于该账号自身的权限，以及项目开启的门禁。只读评审线程在推送协商阶段即被拒绝。

## 其它 Git 主机（PAT）

令牌先取环境所属项目的 `git/<主机>/token`，没有再取全局的。

| 环境 | 能做什么 |
|---|---|
| 属于项目，且项目绑定了 `https://` 仓库地址 | 只能读写该仓库（`git-upload-pack` 与 `git-receive-pack`，以及该仓库的 Git LFS 接口）。仓库路径须与项目的仓库地址完全一致（不区分大小写，忽略 `.git` 后缀）；同主机上的其它仓库与其它主机一律 403，原因「这个 orb 只能访问项目仓库」 |
| 不属于项目，或项目没有 `https://` 仓库地址 | 在配置了令牌的主机上，任意仓库只读；推送、LFS 上传与改动文件锁一律 403 |

绑定了仓库的环境里，地址改写只覆盖项目仓库这一个前缀；其它 `https://` git 地址照常直连公网、不带令牌，公开仓库仍可匿名克隆。

## Oryn 托管仓库

托管项目的环境只能读写本项目的托管仓库，同一 Oryn 地址上别的托管仓库返回 403。这些请求在控制面本地处理，不转发、不带任何令牌；只读评审线程不能推送；推上来的对象先过 `git fsck`。托管项目没有绑定外部仓库地址，其它主机按「不属于项目」的只读规则处理。

你在自己电脑上经 `/git/` 访问托管仓库时，控制面只认设备令牌，浏览器的登录会话不能用。

## Git LFS

LFS 与 git 用同一套仓库与读写规则，经出站代理注入同一个令牌。下载算读；上传对象、建锁、解锁与推送前的锁校验算写。所以不属于项目的环境不能上传，只读评审线程也不能。

令牌同样不进环境：LFS 批量接口的请求与响应都由代理解析后重写，上游在响应里回显或新签发的凭据会被去掉；存放对象的其它主机（对象存储的签名地址）由环境直连。被拒时 `git lfs` 输出的原因以 `oryn: ` 开头。

## 推送 / 开 PR 门禁

门禁是项目级配置，在项目编辑器的「推送 / 开 PR 门禁」里开启，默认关闭。它由出站代理强制执行，不依赖环境里的程序配合：

| 门禁 | 效果 |
|---|---|
| 推送门禁 | 经出站代理推送到 github.com 的每个 `refs/heads/*` 新提交，都必须先有本环境 `push` 级以上的 `github_prepare` 通过记录 |
| PR 门禁 | 创建 PR 时，head 提交必须有 `pr` 级通过记录；PR 正文还要包含指定的二级标题，并可要求含 `Fixes`、`Closes` 或 `Resolves #N` 形式的关闭引用 |

`github_prepare` 在线程工作目录里依次检查：HEAD 不是 detached；当前分支不是默认分支（发布线程例外）；相对默认分支有新提交；运行修复命令并把改动并入 HEAD；工作树干净；每个提交的作者等于线程身份的提交身份；运行检查命令；`pr` 级再运行测试命令。修复、检查、测试命令的时限依次为 600、600、3600 秒。跳过这三条命令必须写明原因，产生的记录带跳过标记，同样放行，并计入审计。

推送门禁开启时还有一条默认分支规则：只有进行中的发布任务能推送或改写默认分支，其余线程一律被拒。这一条在出站代理执行，不依赖环境内 `orbd` 的检查。

### 由触发规则带来的线程限制

GitHub 触发规则建立的线程可能另有三项限制。出站代理每处理一个写请求都向控制面现查一次；现查失败时三项都按开启处理。

| 限制 | 来源 | 效果 |
|---|---|---|
| 只读评审 | 由 PR 打开事件（`pull_request_opened`）触发的规则建立的线程 | 拒绝推送（推送协商阶段就回 403）、创建 PR、合并与一切改 ref 的 API |
| 评审只发 COMMENT | 规则选项「评审只发 COMMENT」 | 评审只放行 `COMMENT` 与不带事件的待提交评审，`APPROVE` 与 `REQUEST_CHANGES` 被拒 |
| 实现需授权 | 规则选项「实现需授权」 | 创建 PR 前必须已获实现授权 |

### 失败即拒绝

推送门禁、PR 门禁或任一项线程限制开启时，写请求体超过 1 MiB、带压缩编码、无法解析，或受管控的 GraphQL 参数无法静态求值，一律拒绝。无论门禁是否开启，修改或删除 Oryn 自己的 webhook 都始终被拒。

被拒的推送在 git 里显示为 `! [remote rejected] HEAD -> <分支> (oryn: <原因>)`；REST 与 GraphQL 请求回 403，正文为 `oryn: <原因>`。被拒的请求不转发，但照样记一行审计。

触发规则与门禁的配置见[GitHub 自动化](/guide/automation/github-automation/)。

## 令牌无法按仓库收窄

<Aside type="caution">
GitHub OAuth App 的令牌**不能按仓库收窄**，对账号能看到的全部仓库都有效；出站代理也不按仓库拦截 github.com。线程能做什么，只取决于它所用账号的权限。
</Aside>

因此：

- 全自动线程应使用「Agent 账号」，并且这个账号只被邀请到确实需要的仓库，权限给到够用即可。
- 不要把有大量组织权限的个人账号设为「Agent 账号」。
- 「任何人」档规则与外部 PR 评审由不可信输入驱动，它们只用「Agent 账号」；「Agent 账号」不可用时宁可不跑，也不退回到「我的账号」。
