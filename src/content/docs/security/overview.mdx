_本页回答：把代码和凭据交给 Oryn 时，边界在哪里？_

## 信任假设

执行环境（orb）里的 Agent 有 root：开发镜像给 `user` 配了免密 sudo。Oryn 因此把环境当作运行不可信代码的地方来隔离，下面四条边界都建立在这个假设上：不指望环境里的进程守规矩，而是让它拿不到不该拿的东西。

环境的网络默认不做隔离。在默认网桥上，环境能访问宿主上的所有服务、局域网、云厂商元数据地址，以及别的环境；Docker 驱动默认去掉容器的 `NET_RAW` 与 `NET_ADMIN` 能力，即使在容器内是 root 也不能发原始包或改路由与防火墙。专用网桥与防火墙规则见[网络隔离与加固](/admin/install/network-isolation/)。

## 凭据隔离

默认 `proxy` 模式下，环境里的配置只有 `oryn-ph-…` 占位符。真实的 API Key 与 Git 令牌存在控制面的加密密钥库里，请求经出站代理时由控制面按上游主机注入，响应里回显的凭据也会被脱敏回占位符。显式设为 `env` 模式的密钥和未绑定上游主机的模型 Key 是例外，它们以环境变量下发。

详见[凭据隔离与出站代理](/security/credentials/)。

## Git 访问范围

github.com 用 OAuth 账号令牌，环境能读写哪些仓库取决于该账号自身的权限，项目可以另开推送 / 开 PR 门禁。其它 Git 主机（PAT）上，绑定了仓库的环境只能读写那一个仓库，未绑定的只能只读克隆。托管项目的环境只能读写本项目的托管仓库。

详见[Git 访问范围与门禁](/security/git-scope/)。

## 单向信任

环境令牌在每次创建、唤醒、拍快照后轮换。你自己机器上的 Runner 只接收不含密钥的配置，经控制面中转访问模型、记忆与 SSH 主机，密钥从不下发；普通环境里的 Agent 也无法操控 Runner。

详见[令牌、设备与单向信任](/security/tokens-trust/)。

## 外部内容不变成指令、不带走数据

全局助手与 Space 协调者运行在控制面的协调沙箱里，沙箱唯一的出口是回环上的出站代理端口。网页、搜索结果、MCP 返回等外部内容都作为不可信数据交给助手。后台研究把上网与读私有数据拆给两个研究员：上网的研究员只拿到话题的标题与问题，`read` 只能读公网网址，读不到本地文件与别的对话；读私有数据的研究员不能上网、没有内置工具，MCP 工具只能调你勾选的那几个，由出站代理逐个请求过滤。网页、邮件、日历带来的发现只交给一轮只读的主线处理。

详见[协调沙箱与不可信输入](/security/sandbox-untrusted/)。
