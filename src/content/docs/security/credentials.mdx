_本页回答：API Key 和令牌为什么不在环境里？_

执行环境（orb）里的 Agent 有 root，Oryn 把环境当作运行不可信代码的地方来隔离。凭据的做法是让真实值始终留在控制面，环境里只有占位符；请求离开环境时经过控制面的出站代理，由代理换上真实值。配置密钥的操作见[模型与密钥](/guide/agent/models-and-keys/)与[密钥与环境变量](/guide/projects/secrets/)。

## 占位符与注入

默认 `proxy` 模式下，导入的 `models.yml` 里的明文 API Key 与 `git/*` 令牌存进控制面用主密钥加密的密钥库，下发到环境的配置只含 `oryn-ph-…` 占位符。环境里的请求经 `orbd` 的本地端口 `127.0.0.1:7811` 回到控制面，控制面按密钥绑定的上游主机注入真实值后再转发。

一个密钥能注入到哪些请求，由它绑定的上游主机（`hosts`）决定：

- `models.yml` 里 `providers.<key>.apiKey` 只能引用该模型供应商自己的密钥 `omp/models/<key>/apiKey`。导入时，这个密钥的 `hosts` 取该供应商 `baseUrl` 与各模型 `baseUrl` 的全部主机。
- `models.yml` 里不允许引用 `git/*` 密钥。
- 其它 `${oryn:secret:…}` 引用必须指向 `hosts` 非空的密钥，而且只注入到 origin 主机与 `hosts` 匹配的路由。
- `hosts` 为空的密钥只能注入到它自己供应商的路由，其它任何路由都不行。

## 回显脱敏

上游在响应里回显的凭据，出站代理会把它脱敏回占位符，Agent 从响应里也读不到真实值。经代理的 WebSocket / Upgrade（101）连接只对响应头做回显脱敏，不改写升级后的字节流，否则会破坏其分帧。

## Git 请求怎样经过代理

环境里的 git 请求同样经 `orbd` 的本机代理（`127.0.0.1:7811`）到达控制面，由控制面注入 `git/<主机>/token` 后转发到 `https://<主机>/…`，令牌从不进入环境。为此 `orbd` 在环境的 `~/.gitconfig` 里写两类条目：把该地址前缀的 `https` 改写成 `http`（主机与 `owner/repo` 路径不变），并让这台主机的 http 请求以代理形式发给本机代理。所以 `git remote -v` 显示的仍是 `http://github.com/<owner>/<repo>`，`gh` 不带 `-R` 也能从 remote 推断仓库。控制面按环境所属项目决定放行哪些仓库，规则见[Git 访问范围与门禁](/security/git-scope/)。

项目级的 Git 令牌也只由出站代理注入、不进环境。代理在每次 git 请求时现取令牌，改值立即生效。

### 被 `NO_PROXY` 覆盖的主机

改写后的地址是明文 http。git 一旦按 `NO_PROXY` / `no_proxy` 绕过本机代理，就会直连该主机的 80 端口：请求不带令牌，但网络上的中间人能替换 refs 与代码。因此 `orbd` 在写上述条目之前，先读 setup 环境里的 `NO_PROXY` 与 `no_proxy`；命中的主机不写改写，也不写代理，remote 保持 `https://`，经 TLS 直连、不带令牌：公开仓库照常可读，私有仓库与推送会明确失败。setup 日志会记一条 `warning: NO_PROXY/no_proxy covers <host> …`，把该主机从 `NO_PROXY` 与 `no_proxy` 里去掉、重新唤醒环境即可恢复。

这个判定只看 setup 时的环境：Agent 在自己的 shell 里临时设置的 `NO_PROXY` 不在防护范围内。Agent 本来就能直连公网下载代码，只是这样拿不到令牌。

## 哪些值会以环境变量下发

以下几类值不经出站代理，而是作为环境变量进入环境：

| 情形 | 说明 |
|---|---|
| 显式设为 `env` 模式的自定义密钥 | 由你选择降级 |
| 未绑定上游 `hosts` 的模型 Key | 只有供应商自己的 `omp/models/<key>/apiKey` 会走这条降级；它一旦绑定了上游主机（`hosts` 非空），就不允许降级 |
| 项目级环境变量 | 只下发给本项目的环境（setup 脚本、Agent、受管服务），别的项目看不到；在环境下次启动时生效 |

<Aside type="caution">
以环境变量下发的值以明文存在于环境里，不受占位符注入与回显脱敏的保护，环境里的 Agent 能读到它们。
</Aside>

Runner 线程与协调宿主不下发项目级条目；全局助手与 Space 协调者也没有读写项目级条目的工具。Runner 收到的配置见[令牌、设备与单向信任](/security/tokens-trust/)。
