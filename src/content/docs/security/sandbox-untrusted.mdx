_本页回答：外部内容进来时怎样不变成指令、不带走数据？_

外部内容有两个入口：全局助手自己读到的网页、搜索结果、MCP 返回与工作线程输出；以及 Oryn 外面的人能触发的自动化（GitHub 触发规则的「任何人」档与定时任务的入站 Webhook）。这些内容都只作为不可信数据交给 Agent，不作为指令；能挡住后果的，是 Agent 拿得到的凭据和出口。

## 协调沙箱只有一个出口

全局助手与 Space 协调者不在执行环境（orb）里，而在控制面内置的协调宿主里运行。协调宿主按需拉起协调进程，用独立系统账号、Landlock LSM、seccomp-bpf 与 Linux 命名空间围成严格的沙箱；沙箱里唯一能连的，是回环上通往控制面出站代理的端口。

| 层 | 限制 |
|---|---|
| 工具 | 只开放指定的内置工具：Space 协调者只有 `read` 与 `write`；全局助手是 `read`、`write`、`web_search`、`generate_image`。技能、扩展、规则、LSP、项目 MCP 等一律关闭；`bash`、`eval`、终端、设置写入等命令到不了 Agent |
| 环境变量 | 从零构造，只有少量固定变量；全局助手另有联网代理地址与 MCP 路由凭据 |
| 文件 | 下发的模型配置里只有占位密钥；每次启动前重写一遍。全局助手的文件库以只读方式同步进来 |
| Landlock | 只有协调宿主自己的 HOME 目录可写且不可执行；可执行的只有 Agent 本体与它的 ELF 解释器；内核 Landlock ABI ≥ 4 时 TCP 只能连出站代理端口、不能监听任何端口；ABI ≥ 6 时信号不出沙箱 |
| seccomp | 只放行 TCP socket，`AF_UNIX`、UDP、netlink 等一律拒绝；调整资源上限与调度的调用只能作用于自身 |
| 权限 | `no_new_privs`，能力集与边界集清空；root 部署时降权到本实例的专用账号 |
| 命名空间 | 能建就建：独立的网络（只有回环）、PID、IPC、UTS 命名空间 |

不同部署方式能得到的隔离程度不同，例如在 Docker 里运行的控制面没有命名空间，只有文件隔离与按端口限制的网络；有的组合下协调功能不可用。逐项对照见[协调宿主](/admin/components/coordinator/)。

## 联网与 MCP 都经控制面

沙箱本身连不到外网。全局助手的联网请求经控制面的正向代理出去，代理在建立连接的那一刻按实际要连的 IP 判定，只连公网地址：回环、私网、链路本地（含云厂商元数据地址）、组播、CGNAT 等一律回 403 `destination is not a public address`。因为判定针对实际连接的 IP，解析到内网的域名与 DNS 重绑定同样被拒。

配置键 `coordinator.web_allow_hosts` 是公网判定的例外清单，用来放行你明确想让助手访问的内网服务。清单里的服务对助手完全可达，网页里的注入指令同样能让助手去读它们，只放你愿意让助手读到的地址。「设置 → 全局助手」里的联网总开关关闭后，代理对一切联网请求回 403。

MCP 服务器的鉴权头由控制面注入，不进沙箱：沙箱里的 MCP 配置只有路由地址和一个 MCP 路由凭据。控制面每次启动随机生成这个凭据，只交给全局助手；出站代理对每个 MCP 请求先核对它，不符一律 403。Space 协调者既没有联网，也没有 MCP 工具。

网页、搜索结果与 MCP 的返回都作为不可信数据交给助手。删除、让未登录的人能访问的分享，以及密钥、凭据与安全相关设置，助手不能直接执行，要你在确认卡上点「是」；确认卡 24 小时没人答就过期。

## 公开的自动化入口

GitHub 触发规则的「任何人」档与定时任务的入站 Webhook 让 Oryn 外面的人也能启动 Agent。外部内容只放进 `<untrusted-…-content>` 数据块（例如 Webhook 的 `<untrusted-webhook-content>`），不作为指令。真正的边界在凭据上：

- 这类线程都是全自动线程。
- GitHub 只用「Agent 账号」，不回退到「我的账号」；「Agent 账号」不可用时，Webhook 的这次运行失败（`github_agent_required`）。
- SSH 只能用允许全自动线程使用的主机。
- 开着「交给助手」时，Webhook 运行的结果只交给主线受限的一轮：只能读，能选择不发言，与后台研究的网页、邮件发现走同一机制。

<Aside type="caution">
项目级密钥与环境变量照常注入该项目的环境。能调用 Webhook 地址、或能在「任何人」档规则下发言的人，就能把内容送到一个拿得到这些值的 Agent 面前。对外开放的入口放在不带敏感密钥的项目里。
</Aside>

签名、数据块标签、运行前闸门与限流只决定谁能触发、要不要运行，不能代替上面这些凭据与权限限制。Webhook 的配置见[入站 Webhook](/guide/automation/webhooks/)，GitHub 规则见[GitHub 自动化](/guide/automation/github-automation/)。

## 后台研究的两类研究员

后台研究缺省关闭。打开后，控制面在协调宿主里驱动两个隐藏的研究员，把上网与读私有数据分给不同的研究员。研究员只在一次研究运行期间存在，上一次的上下文不会带进下一次。

**公网研究员**手里没有私有数据：

- 内置工具只有 `web_search` 与 `read`，不加载技能；没有 MCP 凭据。
- `read` 只读公网 http(s) 网址和本会话的 `local://`；本地路径、`file://`、`skill://` 等内部协议、`localhost`，以及写成字面量的回环、私网、链路本地、CGNAT 与 `0.0.0.0/8` 地址一律被拒。提示词里 `@路径` 的自动读取也被关掉。
- 提示词由控制面拼装，只含话题的种类、标题、问题、上一次的报告与当天日期；当时的回答与任何对话内容都不交给它。它即使被网页注入，也没有私有数据可泄露。
- 全局助手的联网总开关关着时，公网跟进不运行。

**私有研究员**不能上网：

- 没有任何内置工具，读不了文件；没有联网代理。
- 部分运行里有宿主工具，全部只读：列出与读取线程、定时任务、项目与统计，以及助手记忆开着时的历史与记忆检索。
- 只有检查 MCP 的运行里，它才拿到一个独立的**研究凭据**，拿不到全局助手的 MCP 凭据。持研究凭据的请求只能访问你在「研究可用工具」里勾选过工具的服务器；`tools/call` 只放行名单里的工具，名单外的工具与其它方法由控制面直接回错误，上游收不到请求。

<Aside type="caution">
「研究可用工具」里只勾不会对外发送数据、不会改动任何东西的读取工具。服务器自报的只读标记（`readOnlyHint`）是服务器自己的说法，不是保证，所以对话框不预先勾选任何工具。发送邮件、创建日历事件这类工具一旦勾上，网页或邮件里的注入就能借研究员调用它们。
</Aside>

公网研究与 MCP 检查的发现进主线时，主线先以受限方式重启：内置工具只有 `read`，没有联网代理与 MCP 凭据，宿主工具只剩只读的一组与选择不发言。这一轮结束后主线下一次启动恢复完整工具。你恰好在这一轮里发来的消息由受限的 Agent 回答，下一条消息起恢复。

研究的配置见[后台研究与跟进](/guide/assistant/research/)与[助手联网、MCP 与后台研究](/admin/components/assistant-network/)。

## 残余风险

以下是来源文档列出的、当前设计没有消除的风险。

### 协调宿主

- 联网按协调宿主只有一份策略，不按 Agent 区分：Space 协调者与全局助手连的是同一个代理端口。Space 协调者不联网，靠的是它没有联网代理变量、内置工具里没有 `web_search` 与生图，而不是代理按调用方拒绝。MCP 不同：出站代理对每个 MCP 请求核对只有全局助手持有的凭据。
- 协调宿主里的各个 Agent（全局助手与 Space 协调者）运行在同一个沙箱里：同一个 uid、共享 HOME，`/proc` 可读。同宿主的 Agent 能读到别的 Agent 进程的环境变量（含 MCP 路由凭据 `ORYN_MCP_TOKEN`）和 HOME 里的文件。沙箱隔开的是协调宿主与宿主机的其它部分，不是同一宿主里的各个协调 Agent。
- 全局助手会读网页、搜索结果、MCP 返回与工作线程的输出。这些内容都以不可信数据交给它，但注入的指令仍可能诱导它做事：给工作线程或 Runner 线程发消息、读写线程文件、在自己的电脑上执行命令、经联网把读到的内容发出去。删除与对外公开要你点确认卡；新建、修改、归档、发消息等写类操作直接执行并写审计，可在自动化操作记录里查看；联网、MCP、操作助手的电脑以及 artifact 的创建与修改不写审计，只在对话转录里留下工具卡。
- 没有网络命名空间时，沙箱内进程能向**任意地址**的出站代理端口号发起 TCP 连接（Landlock 只按端口管）。
- `/proc` 只读可见，沙箱外其它进程的命令行可读（环境与内存读不到）。
- 不防资源耗尽（内存、磁盘、CPU）。
- root 部署、没有 PID 命名空间且 Landlock ABI 低于 6 时，沙箱能给同为降权账号的其它协调宿主进程发信号（同一所有者，不出信任域）。
- 没有网络命名空间时，放行的 stream `socketpair` 的一端可以 `bind` 到宿主上一个尚未被占用的 abstract unix 名字：只能抢占名字，不能借它连接或收发任何东西。
- HOME 不可执行这一条挡不住执行 HOME 里的代码：经 ELF 解释器或 `memfd_create` 加 `execveat` 都能运行。隔离不依赖这一条：能执行的代码仍在同一个沙箱里，受同样的 Landlock、seccomp、命名空间与降权约束。
- 没有 PID 命名空间时，沙箱内用 `setsid` 脱离进程组的进程不随子进程结束。自动创建的专用账号会在子进程退出后按 uid 清扫；**显式指定的账号不清扫**，残留进程会一直留着，下次拉起时独占检查发现它们、协调功能不可用，需要手工结束。非 root 部署（沙箱与控制面同一用户）同样不清扫。
- TCP Fast Open 在实测内核上与普通连接一样被 Landlock 拒绝，自检会逐项验证；没有另加 seccomp 规则。

### 后台研究

- 私有研究员与受限的主线不联网，靠的是它们没有联网代理变量和相应的内置工具，与 Space 协调者相同，而不是出站代理按调用方拒绝。
- `read` 跟随重定向时不检查目标主机：公网页面可以把公网研究员的 `read` 重定向到回环上的出站代理端口。那里它只能发 GET，MCP 路由要它没有的凭据，它手里也没有私有数据，所以不另做处理。
- MCP 请求的过滤假定沙箱里没有哪个研究员能自己构造任意 HTTP 请求。以后给研究员加任何能发任意请求的工具之前，必须先重看这层过滤。
- 研究凭据同样以环境变量出现在私有研究员的进程里，同宿主的 Agent 能从 `/proc` 读到；它能做的事是助手凭据的子集。

### 助手的电脑

助手的电脑是一台普通的执行环境，不在协调宿主里，网络、出站策略与密钥下发和不属于项目的环境相同。电脑里能执行任意命令、能联网，助手读到的不可信内容可以经它产生外部副作用。不希望这样时，在网络隔离上收紧这台环境（见[网络隔离与加固](/admin/install/network-isolation/)），或不要让助手用电脑处理不可信内容。
